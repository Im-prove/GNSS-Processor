## The coordinate-range question

`[-90, 90]` is not a claim that a GNSS receiver is accurate to ±90° or has a special GNSS-specific tolerance. It is the latitude domain for ordinary geographic coordinates, from the South Pole to the North Pole; NOAA's NGS geodesy material describes latitude running from 90° south through the equator to 90° north ([reference](https://geodesy.noaa.gov/PUBS_LIB/basgeo.pdf)). The code check only rejects values that cannot be represented in that coordinate convention. A value of `89.9°` passes this range check even if it is nowhere near the robot's expected route; route plausibility needs a separate rule.

## How to explain an assumption in the interview

For each choice, separate the assignment requirement from the implementation policy. For example, 10 Hz implies a nominal 100 ms interval, but the assignment gives no jitter tolerance. This implementation uses a configurable maximum outage of 1500 ms and does not enforce an exact 100 ms cadence.

### Coordinate vocabulary

The code expects latitude/longitude in angular degrees, not projected coordinates such as UTM or State Plane. A coordinate reference system/datum is not represented in `GnssFrame`; in a real application it should be documented at the interface boundary. The numeric range check only tests the familiar geographic angle domain. It does not check datum, epoch, precision, route membership, or fix accuracy.
